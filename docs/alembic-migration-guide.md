## 🤔 Alembic이란?

Alembic은 SQLAlchemy를 위한 데이터베이스 마이그레이션 도구입니다.

### 주요 기능
- **자동 마이그레이션 생성**: SQLAlchemy 모델 변경 사항을 자동으로 감지
- **버전 관리**: 데이터베이스 스키마를 Git처럼 버전별로 관리
- **롤백 지원**: 이전 버전으로 되돌리기 가능
- **프로덕션 안전성**: 점진적 배포 및 검증 가능

### 왜 필요한가?
```python
# SQLAlchemy 모델 변경
class Category(Base):
    __tablename__ = "categories"
    id = Column(UUID(as_uuid=True), primary_key=True)
    name = Column(String, nullable=False)
    emoji = Column(String, nullable=False)
    order = Column(Integer, default=0)  # ✨ 새 필드 추가
```

위처럼 모델을 수정해도 **실제 데이터베이스 테이블은 자동으로 변경되지 않습니다**.
Alembic을 사용하면 이런 변경사항을 **안전하게 데이터베이스에 적용**할 수 있습니다.

## 📚 마이그레이션 기본 개념

### 1. 마이그레이션 파일
```
backend/alembic/versions/
├── abc123_initial_schema.py          # 첫 번째 마이그레이션
├── def456_add_category_order.py      # 두 번째 마이그레이션
└── ghi789_add_transaction_tags.py    # 세 번째 마이그레이션
```

각 파일은 **업그레이드**와 **다운그레이드** 함수를 포함합니다:

```python
def upgrade():
    """데이터베이스를 새 버전으로 업그레이드"""
    op.add_column('categories', sa.Column('order', sa.Integer(), nullable=True))

def downgrade():
    """이전 버전으로 롤백"""
    op.drop_column('categories', 'order')
```

### 2. 버전 체인
```
initial_schema (abc123)
    ↓
add_category_order (def456)
    ↓
add_transaction_tags (ghi789) ← HEAD (최신)
```

Alembic은 이 체인을 따라 순차적으로 적용/롤백합니다.

### 3. alembic_version 테이블
Alembic은 자동으로 `alembic_version` 테이블을 생성하여 **현재 적용된 버전**을 추적합니다.

```sql
SELECT * FROM alembic_version;
-- version_num
-- ghi789
```

## 🚀 마이그레이션 생성 및 적용

### 전체 워크플로우

```
1. SQLAlchemy 모델 수정
    ↓
2. 마이그레이션 파일 자동 생성
    ↓
3. 마이그레이션 파일 검토 및 수정
    ↓
4. 마이그레이션 적용
    ↓
5. 동작 확인
```

---

### Step 1: SQLAlchemy 모델 수정

예시: Category 모델에 `order` 필드 추가

```python
# backend/app/models/category.py
from sqlalchemy import Column, String, Integer, ForeignKey
from sqlalchemy.dialects.postgresql import UUID
import uuid

class Category(Base):
    __tablename__ = "categories"

    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    user_id = Column(UUID(as_uuid=True), ForeignKey("users.id"), nullable=False)
    name = Column(String, nullable=False)
    emoji = Column(String, nullable=False)
    order = Column(Integer, default=0, nullable=False)  # ✨ 새로 추가
    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
```

---

### Step 2: 마이그레이션 파일 자동 생성

#### Docker 컨테이너 내부에서 실행

```bash
# 1. 백엔드 컨테이너 접속
docker-compose exec backend bash

# 2. 마이그레이션 파일 생성
alembic revision --autogenerate -m "add order field to categories"

# 출력:
# INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
# INFO  [alembic.autogenerate.compare] Detected added column 'categories.order'
# Generating /app/alembic/versions/abc123_add_order_field_to_categories.py ... done
```

#### 로컬에서 실행 (Docker 없이)

```bash
# backend/ 디렉토리에서
cd backend
alembic revision --autogenerate -m "add order field to categories"
```

#### 옵션 설명
- `revision`: 새 마이그레이션 파일 생성
- `--autogenerate`: 모델과 DB를 비교하여 자동 생성
- `-m "메시지"`: 마이그레이션 설명 (Git 커밋 메시지처럼)

---

### Step 3: 마이그레이션 파일 검토

생성된 파일을 **반드시 검토**하세요!

```python
# alembic/versions/abc123_add_order_field_to_categories.py

"""add order field to categories

Revision ID: abc123
Revises: def456
Create Date: 2025-10-19 14:30:00.123456
"""

from alembic import op
import sqlalchemy as sa

# revision identifiers, used by Alembic.
revision = 'abc123'
down_revision = 'def456'  # 이전 버전
branch_labels = None
depends_on = None

def upgrade():
    # ### commands auto generated by Alembic - please adjust! ###
    op.add_column('categories', sa.Column('order', sa.Integer(), nullable=False))
    # ### end Alembic commands ###

def downgrade():
    # ### commands auto generated by Alembic - please adjust! ###
    op.drop_column('categories', 'order')
    # ### end Alembic commands ###
```

#### 자주 수정하는 부분

**1. 기본값 설정**
```python
# Alembic이 자동 생성한 코드
op.add_column('categories', sa.Column('order', sa.Integer(), nullable=False))

# 기존 데이터가 있다면 에러 발생! 수정 필요:
op.add_column('categories', sa.Column('order', sa.Integer(), nullable=False, server_default='0'))
```

**2. 데이터 마이그레이션 추가**
```python
def upgrade():
    # 1. 컬럼 추가 (nullable=True로 임시 생성)
    op.add_column('categories', sa.Column('order', sa.Integer(), nullable=True))

    # 2. 기존 데이터에 순서 부여
    op.execute("""
        UPDATE categories
        SET order = row_number() OVER (PARTITION BY user_id ORDER BY created_at) - 1
    """)

    # 3. NOT NULL 제약 조건 추가
    op.alter_column('categories', 'order', nullable=False)
```

```python
# backend/app/models/category.py
```

### 예제 2: 컬럼 타입 변경

#### 시나리오
Transaction의 `amount` 필드를 Integer → Numeric(10, 2)로 변경 (소수점 지원)

#### 1. 모델 수정
```python
# backend/app/models/transaction.py
from sqlalchemy import Numeric

class Transaction(Base):
    # 기존: amount = Column(Integer, nullable=False)
    amount = Column(Numeric(10, 2), nullable=False)
```

#### 2. 마이그레이션 생성 후 수정
```python
def upgrade():
    # 1. 새 컬럼 추가
    op.add_column('transactions', sa.Column('amount_new', sa.Numeric(10, 2), nullable=True))

    # 2. 데이터 복사
    op.execute("UPDATE transactions SET amount_new = amount::numeric(10,2)")

    # 3. 기존 컬럼 삭제
    op.drop_column('transactions', 'amount')

    # 4. 새 컬럼 이름 변경
    op.alter_column('transactions', 'amount_new', new_column_name='amount', nullable=False)

def downgrade():
    op.add_column('transactions', sa.Column('amount_new', sa.Integer(), nullable=True))
    op.execute("UPDATE transactions SET amount_new = amount::integer")
    op.drop_column('transactions', 'amount')
    op.alter_column('transactions', 'amount_new', new_column_name='amount', nullable=False)
```

### 예제 3: 테이블 추가

#### 시나리오
태그 기능을 위한 `tags` 테이블 추가

#### 1. 모델 생성
```python
# backend/app/models/tag.py
class Tag(Base):
    __tablename__ = "tags"

    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    user_id = Column(UUID(as_uuid=True), ForeignKey("users.id"), nullable=False)
    name = Column(String, nullable=False)
    created_at = Column(DateTime, default=datetime.utcnow)
```

#### 2. 마이그레이션 자동 생성
```bash
docker-compose exec backend alembic revision --autogenerate -m "add tags table"
```

Alembic이 자동으로 `CREATE TABLE` 구문 생성:
```python
def upgrade():
    op.create_table('tags',
        sa.Column('id', sa.UUID(), nullable=False),
        sa.Column('user_id', sa.UUID(), nullable=False),
        sa.Column('name', sa.String(), nullable=False),
        sa.Column('created_at', sa.DateTime(), nullable=True),
        sa.ForeignKeyConstraint(['user_id'], ['users.id'], ),
        sa.PrimaryKeyConstraint('id')
    )
```

### 예제 4: 인덱스 추가

```python
class Transaction(Base):

```

### 문제 3: 자동 생성이 변경사항을 감지하지 못함

**원인**:
1. `env.py`의 `target_metadata` 설정 누락
2. 모델을 import하지 않음

**해결**:
```python
# alembic/env.py
from app.models.user import User
from app.models.category import Category
from app.models.transaction import Transaction
from app.core.database import Base

target_metadata = Base.metadata  # 중요!
```

### 문제 4: "column contains null values"

```
ERROR: column "order" of relation "categories" contains null values
```

**원인**: `NOT NULL` 제약이 있는 컬럼을 기존 테이블에 추가

**해결**:
```python
def upgrade():
    # 방법 1: server_default 사용
    op.add_column('categories',
        sa.Column('order', sa.Integer(), nullable=False, server_default='0')
    )

    # 방법 2: 2단계로 추가
    op.add_column('categories', sa.Column('order', sa.Integer(), nullable=True))
    op.execute("UPDATE categories SET order = 0 WHERE order IS NULL")
    op.alter_column('categories', 'order', nullable=False)
```

## 🎯 베스트 프랙티스

### 1. 마이그레이션 파일은 항상 검토
자동 생성된 파일을 맹신하지 말고 **반드시 검토 후 수정**

### 2. 명확한 메시지 작성
```bash
# ❌ 나쁜 예
alembic revision -m "update"

# ✅ 좋은 예
alembic revision -m "add order field to categories for drag and drop"
```

### 3. 롤백 시나리오 테스트
```bash
# 업그레이드
alembic upgrade +1

# 다운그레이드 테스트
alembic downgrade -1

# 다시 업그레이드
alembic upgrade +1
```

### 4. 프로덕션 배포 전 SQL 검토
```bash
alembic upgrade head --sql > migration.sql
# migration.sql 파일 검토 후 수동 실행
```

### 5. 마이그레이션은 Git에 커밋
```bash
git add alembic/versions/abc123_add_order_field.py
git commit -m "feat: add order field to categories for sorting"
```

### 6. 데이터 백업
중요한 프로덕션 마이그레이션 전에는 **반드시 백업**:
```bash
docker-compose exec postgres pg_dump -U household_user household_ledger > backup.sql
```
